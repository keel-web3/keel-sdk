# KOC1 v1 vectors

Run from the repository root:

```sh
node packages/ordinals-collections/spec/vectors/check.mjs
```

The only runtime dependency is pinned `@noble/curves` 1.9.7 (with its own hash
package). Node's `crypto` supplies hashing. To install only this package without
changing the workspace lockfile:

```sh
cd packages/ordinals-collections
npm install --workspaces=false --package-lock=false --ignore-scripts
```

If a machine-wide npm minimum-release-age setting produces an invalid cutoff,
use `--min-release-age=0` for this pinned installation. Do not regenerate the
workspace lockfile as part of K0-T02; the package is private and K1's workspace
integration owns that change.

`generate.mjs` rewrites only the 20 generated suite JSON files. `source.json` is
pinned source provenance, `testnet4-block.json` is pinned public evidence, and
`schema.json` describes suite/case structure. Generation performs no network
reads. The checker validates the schema without a schema-library dependency,
compares exact regenerated bytes, re-evaluates all cases, checks numbered rule
coverage, and checks literals copied independently from research §1.12. It also
mutates proofs, headers, transaction bytes, CBOR, addresses and schema inputs.
A failure exits nonzero. It never edits expected results to make them pass.

Every case has a unique ID within its suite, explicit rule citations, complete
JSON input and expected output. Each case is an independent synthetic universe;
a mutated recipe in a negative case does not revise another case's recipe.
Hashes use the conventions in KOC1.md; the raw public block's display hash and
internal hash are both retained to prevent accidental byte-order conflation.

Synthetic reveals contain placeholder signature bytes. Every reveal has a concrete
commit transaction whose stripped txid matches vin[0]'s prevout. The classifier
reconstructs the envelope's Taproot leaf/control path and matches the commit
output key and parity; it no longer accepts a `commitVerified` boolean.
This authenticates the envelope script, not signatures, annex bytes or admission
by Bitcoin consensus.
Challenge input `entries` supplies independently checked mint form and
location facts; the vector verifies branches and patching against those facts.
Registry authorization and bridge-proof validity are likewise explicit boundary
inputs. K1 implements the actual source adapters and independent Python twin;
K2 executes the escrow scripts in regtest. Boolean interface-policy fixtures are
not evidence of those components having run.

The escrow matrix models CSV and signature **roles**, not a Bitcoin interpreter.
An actual tapscript `NUMEQUAL 2` needs exactly two successful writer checks, so
three nonempty valid writer signatures fail that leaf. Membership is deliberately
not script-enforced. Public small-multiple curve points are deterministic test
inputs, not wallet secrets; no key is generated, used to sign, or printed.

The synthetic linked-header case uses a cheap regtest target as a unit test,
without starting any node; it is not testnet4 chain/difficulty evidence. The real
height-1 header is checked separately. Bitcoin Merkle trees duplicate odd nodes;
KOC1 metadata/member trees promote them. The checker tests this distinction.

Owner-approved E1–E4 are applied and documented in KOC1.md. Passing JS self-check is K0 evidence,
not K1 cross-language agreement, onchain execution, full shell implementation,
public readiness, or independent cross-language validation.
