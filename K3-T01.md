## Implementation

Added the browser entry point `@keel/ordinals-collections/shell` under
`packages/ordinals-collections/src/shell/`, with API/scope documentation there.
`verifyShell()` derives self from location and returns `member`, `not member`,
`settling`, or `invalid`, reasons, stage checks, rank, covered height C, finality,
entry assurance, per-load fetch/byte statistics and explicit S10–S14 seams.

- S1–S4: raw reveal and commit txids, canonical envelope, exact Taproot
  script/control-block output key and parity, recipe marker, payment, authentic
  confirmation height and charms. A changed witness cannot pass just because
  the stripped reveal txid still matches.
- S5: recipe identity/marker, existing bundle/viewer/indexer references, exact
  body hashes and availability/order. Bodies come from authenticated raw reveal
  envelopes, so runtime requests stay entirely under `/r/`.
- S6–S8: depth; optional S7 work check enabled by default, reconstructed headers,
  testnet4 powLimit and linked successors through h+F; own transaction position
  from K1's fully parsed, Merkle-verified raw block bound to host blockhash.
  Ord inscription numbers are never ordering evidence. Synthetic tests explicitly
  disable optional work checking; block/hash binding remains checked.
- Controls: recipe children in child order, overriding metadata ID, parent and
  confirmation height with recursion evidence before calling K1's control state
  machine. A backdated control arriving too late is ineffective.
- Writers: paged authority children; K1 writer-chain/root/extension validation,
  merge, fixed recipe quorum, and all mint-carried seen/pin commitments. Missing
  and ratchet-rejected writers cast no vote. A stopped third writer does not
  prevent the other two from settling.
- S9: all preceding entries through 1,000 claimed members; above that threshold,
  an explicit 64-entry evenly spaced sample plus independently validated invalid
  challenges reached from original authorities/self. Own entry is always fully
  checked. Proven bad entries are dropped without adding a permanent reputation
  rule. Unknown evidence/resource exhaustion stays settling.

Reused `core.ts`, `controls`, `index/classify`, `index/root`, `merge` and
`challenge`; no second mint, control, writer or merge implementation. Replaced
shared Node hashing/byte dependencies with a small Uint8Array helper and pinned
`@noble/hashes` 1.8.0. Node-facing CBOR/serialization/PSBT adapters retain Buffer
compatibility. Generalized the existing commit authenticator's optional input
index for non-mint reference inscriptions; the mint path still requires vin[0].

The shell graph contains no Node builtins, Buffer global, wallet, signing or
external endpoint. Requests reject redirects, use timeout/response/load budgets,
and cache evidence only within one load. Host best-chain selection, confirmation
and child-index authenticity, and consensus admission remain source assumptions.
S7 does not claim retarget verification.


Final run against the localhost HTTP mock, cold per-load cache:

| Measurement | Result |
| --- | ---: |
| Authority updates | 1,000 |
| Children pages (100/page) | 10 |
| Recursion fetches | **3,010** |
| Response-body bytes | **1,707,075** |
| Walk wall time | **5,526.05 ms** |
| Updates subsequently accepted by K1 writerChain | **1,000** |

Fetch breakdown: 10 children pages, 1,000 inscription records, 1,000 raw reveals,
1,000 raw commits. Each update undergoes stripped-txid and Taproot commit
binding. The chain uses valid empty-delta updates at nondecreasing covered height
106, isolating traversal/authentication overhead. Bytes include JSON carriage,
exclude HTTP headers, and are counted independently by client and mock server.
Wall time excludes fixture creation, server startup and the subsequent chain
acceptance assertion. This measures the browser-side children walk, not the
recursion server's internal UTXO/spender walk or a complete shell/index load.
An earlier run was 7,162.14 ms with the same fetch and byte totals; local timing
is sensitive to concurrent test/build work.

## Open questions and K4 handoff

No task blocker remains.

1. The ticket says an equivocating writer with the same “updateId” is ignored.
   Frozen R31 and its vectors specify siblings with the same **prev**: retain the
   first valid child, ignore subsequent siblings and report both IDs. That is the
   implemented behavior; an entire writer is removed from voting for a failed
   R32 ratchet, rather than an invented equivocation penalty.
2. S10–S14 remain explicit deferred stages: full challenge channels/replay,
   registry additions, audit, owner/burn, art/metadata and bridge verification.
   Discovered challenges conservatively keep finality pending until that layer
   resolves them. The S9 invalid-entry path already checks and removes a proven
   invalid entry outside the sample. No arbitrary next/fork becomes authority.
3. The sampling algorithm is local policy (D17 freezes no algorithm). Results
   remain labeled sampled; neither sample nor writer quorum proves completeness.
   K4's audit and full challenge processing are still needed for that profile.
4. This is a library implementation and mock/browser result, not a deployed
   catalog inscription, public-network signing boundary, 24-hour writer drill or
   independent trust review. The plan's reviewer-before-merge gate remains with
   integration; this ticket creates no merge or PR.
