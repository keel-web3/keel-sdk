# K2-T01 — escrow spends and mint transaction builder

Completed 2026-11-08 on ticket/K2-T01, based on 3b34d5f.

Scope: escrow and transaction builders, test signing helpers, isolated regtest
consensus/mempool tests. No indexer, merge, UI, publication, ord, or public-network
operations. Plan and research were read from the sibling ordinals-orchestra
checkout because their requested paths are absent in this worktree. The frozen
package KOC1 spec supplies E1 and D6/D22 normative corrections.

## Delivery

Unsigned BIP174 v0 PSBTs with BIP371 witness UTXO, internal key, Merkle root and
leaf/control-block fields as applicable. Commit key-path cancellation, canonical
KOC1 mint envelope and metaprotocol tag, recipient/escrow/marker output ordering,
commit/reveal RBF, CPFP, all escrow paths, and BIP340/341 signing helpers.
Mint metadata is split into canonical 520-byte chunks when necessary. Commit
output/leaf/control parity is checked before reveal building; E1 is also checked
on the final signed reveal. RBF preserves protocol outputs and requires explicit
change. Callers select authentic UTXOs, fees, recipe/window eligibility and writer
authorization. Builders currently support P2TR key-path funding only.

## Verification

Bitcoin Core: /usr/local/bin/bitcoind, v28.99.0-2d07384243c9. Regtest only,
listen=0, connect=0, dnsseed=0, discover=0, loopback RPC, allocated non-default
port, unique temporary datadir. Harness stops its daemon and removes its datadir
via teardown on success/failure. No wallet keys or existing node are used.

Command: `pnpm --dir packages/ordinals-collections test`. Result: 35/35 tests
passed, zero skipped; existing frozen checker: 189 cases, 21 suites, 52/52 rules.
Its public testnet4 block is a local pinned fixture, not a network connection.

Regtest subtest names:

1. L_t writers 1+2: refused h+collectAfter-1, accepted h+collectAfter
2. L_t writers 1+3: refused h+collectAfter-1, accepted h+collectAfter
3. L_t writers 2+3: refused h+collectAfter-1, accepted h+collectAfter
4. L_m buyer only: refused h+refundAfter-1, accepted h+refundAfter
5. L_t each single writer fails at maturity
6. L_e each writer pair succeeds before refundAfter; missing writers or buyer fails
7. mint commit/reveal authenticates E1; PSBTs decode; reveal accepted
8. cancelled commit cannot reveal
9. RBF commit and reveal accepted; CPFP child accepted

CSV boundaries use the next candidate block: with escrow confirmed at h, a tip
at h+delay-2 rejects and a tip at h+delay-1 accepts for mining at h+delay.
Accepted spends are broadcast to this regtest and mined. L_e has no timelock,
so a one-block-before-lock test is inapplicable. It is usable immediately with
the buyer and two writers and remains consensus-spendable after refundAfter.
Likewise L_t has no upper expiry; L_m always opens at refundAfter. These are
the exact frozen scripts; no unenforceable upper bound has been introduced.

Additional unit coverage: deterministic unsigned PSBTs and immutable inputs,
E1 commitment mutations, insufficient/dust amounts, duplicate inputs, invalid
keys/delays, RBF protected outputs, absent CPFP output/wrong key, chunked
metadata, and no-early-refund tree/control layout.
