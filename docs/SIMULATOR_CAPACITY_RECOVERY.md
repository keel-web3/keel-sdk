# Simulator capacity recovery

The authorized Gatorrr incident evidence records a requested 200,000,000-gas envelope returned as 50,000,000 by `eth_simulateV1`. The guard correctly rejected that response. A subsequent operator process completed the same saved operation at a fresh block, with a 170,135,114-gas validated wallet budget and 141,779,261 pre-refund gas used. It did not publish or sign. The application retains a module-level WebSocket, so success from a separate process did not resolve its retained connection.

The pinned Sepolia transport handles this concrete response-integrity failure automatically. The subsequent closed-socket recovery below uses the same bounded selection mechanism. It performs at most three connection selections per request, using the existing `wss://ethereum-sepolia-rpc.publicnode.com` endpoint. A known program qualifies its required envelope with public empty calls, bounded by the observed chain policy; ordinary reads use the existing modest control. The exact project response must independently preserve every requested envelope. Small plans can still use providers whose lower cap accommodates their request.

On a confirmed clamp, the unchanged ephemeral simulation can be retried after public qualification and an exact numbered-block hash check. The request is copied before awaiting any I/O, preserving calldata, nonce, fee fields, gas, ordering and flags even if a caller mutates its input. No new provider, state override, signing, submission, new operation or storage payment is introduced. Concurrent readers share qualification; retired sockets close after their current readers finish. Replacement waits for that close, because viem otherwise returns its endpoint-cached socket again. Explicit close prevents a late result from returning as proof.

Missing/enlarged envelopes, wrong-chain or fork evidence, changed snapshots, genuine EVM reverts and symbolic snapshot tags cannot produce an automatic project replay. Exhausted capacity remains a `provider-limit` error with the observed gas cap and attempt count. A subsequent saved-plan read may try again. Full strict transaction validation, pre-refund measurement, selected-chain limits, canonical snapshot checks and byte-exact complete metadata verification remain mandatory.

A separate reproducible defect cached an initial `rpc-unavailable` qualification failure forever: later checks reused the rejected promise without trying a connection. Generic unavailable failures retire that selection and fail the current check. A new saved-plan check performs full qualification at the same endpoint. Confirmed closed sockets during numbered-block simulations now recover within the same check as described below; arbitrary RPC errors and timeouts still fail closed.

The owner's runtime trace confirmed that unknown RPC causes were discarded by the generic classifier. Diagnostics now retain an allowlisted method/phase, bounded numeric RPC code/HTTP status, known error class, transport-code category, cause depth and socket state before classification. Messages, stacks, URLs, params, response data and identities are never copied. The Studio initial-storage boundary emits one sanitized diagnostic event per failed check. This closes an observability gap; it does not identify the existing production failure's cause. The regression with a synthetic unknown RPC code fails on the previous classifier and passes here; cyclic causes and credential/artwork-shaped strings are covered.

`tests/fixtures/gatorrr-simulator-cap-20261009.json` records the supplied IDs and numeric evidence with provenance. Socket responses and short metadata used by tests are synthetic, not production artwork or proof of deployment. Coverage includes initial capacity rejection, retained low-cap connection then eligible replacement, three-attempt exhaustion and fresh retry, concurrency/close, request mutation, small plans and lower block limits, changed snapshot refusal, and full atomic preflight that still rejects wrong metadata, nonce, missing measurement or genuine execution failure.

## Closed socket during the live owner check

The deployed `2245cf6` / SDK `d6e92ca` diagnostic at 2026-10-10 00:42:44.979 UTC identified `SocketClosedError` during the project `eth_simulateV1` request, with socket state 3. It included no numeric RPC code, HTTP status, gas cap or close code/reason. Why the socket closed remains unknown. The previous behavior retired the socket but required another creator click.

The same idempotent simulation now automatically retires/drains that connection, fully qualifies a new connection at the same approved endpoint, verifies the exact numbered snapshot hash, and retries its immutable request. There are at most three attempts total, shared with capacity recovery. Only this read-only simulation is replayed; the transport rejects signing, sending and other unsupported methods before connecting. A symbolic block tag, changed hash, wrong chain/fork, unsupported qualification, genuine execution failure, incomplete gas/nonce evidence or incorrect complete metadata cannot become a passing proof. Explicit transport close still prevents a late proof/reconnection. Call ordering, calldata, value, nonce, fees, selected gas limits and validation flags are copied before I/O. Unknown failures and timeouts do not acquire this retry permission.

A close-event listener captures a numeric code in 1000–4999 and one classified reason (`empty`, `message-too-large`, `rate-limited`, `timeout`, `server-unavailable`, `protocol-error`, `policy-violation`, `other`). No raw close reason, error text, endpoint or payload is retained in diagnostics. Intentional cleanup detaches the listener before closing so it cannot replace the failure evidence. Exhaustion retains the last safe close evidence and bounded attempt count. Codes/reasons in test responses are synthetic, not assertions about the real provider.

The authorized incident fixture is `tests/fixtures/retro-closed-simulation-socket-20261010.json`. Regression coverage includes an actual installed viem/isows WebSocket client against a loopback server closing mid-request, immutable retry in both validation modes, exhaustion, changed/symbolic snapshots, chain/qualification refusal, concurrent cached-socket draining, explicit close, no write/sign admission, caller mutation and full preflight rejection after recovery. ## Confirmed message-size rejection

The deployed `4e24517` / SDK `4c62dd0` trace at 2026-10-10 01:55:07.338 UTC records WebSocket close code 1009, empty reason, during the project simulation. The subsequent public-qualification failures record a provider limit but no numeric cap. These are distinct observations; the final events do not reconstruct every attempt. `tests/fixtures/retro-message-size-20261010.json` preserves their provenance and limits. The trace contains no serialized request/response, so the offending direction and exact message size remain unmeasured.

[RFC 6455](https://www.rfc-editor.org/rfc/rfc6455#section-7.4.1) defines 1009 as rejection of an oversized received message. Reopening the same WebSocket and repeating the whole exchange is not a size recovery. The factory now changes to [PublicNode's documented HTTPS Sepolia endpoint](https://ethereum.publicnode.com/?sepolia=), on the same already approved host, after a confirmed 1009. HTTPS must pass the same override-free public read/strict capacity, fork, nonce and snapshot qualification. Only an unchanged numbered-block simulation may replay, within the same three-attempt budget. HTTPS remains selected for later phases; a third attempt never becomes an unbounded reconnect loop. No registered payload representation, state, gas, order, fees, nonce, validation flag or return bytes are changed or split. HTTPS is not assumed to have compatible capacity: exact envelopes and every full preflight check remain mandatory. Its HTTP 413, capacity exhaustion, unsupported evidence, timeout or real execution failure blocks funding. Redirects are refused.

PublicNode's endpoint page does not state a numeric transport limit. Upstream defaults are not evidence of its configuration: [Geth's WebSocket source](https://github.com/ethereum/go-ethereum/blob/master/rpc/websocket.go) defaults to 32 MiB reads, [its HTTP source](https://github.com/ethereum/go-ethereum/blob/master/rpc/http.go) to 5 MiB request bodies, and [Reth's RPC arguments](https://github.com/paradigmxyz/reth/blob/main/crates/node/core/src/args/rpc_server.rs) define separate configurable request/response limits. None identifies the actual live rejection threshold.

Every failed attempt can emit an allowlisted diagnostic with protocol, attempt number, qualification stage, requested/returned gas, and numeric queued request size/block/call counts. `requestPayloadBytes` is the UTF-8 size of the exact queued method/params JSON, excluding only JSON-RPC `id`/`jsonrpc`; during failed qualification it describes the waiting program, not the small qualification probe. No calldata, identifiers, raw close reason, URL or response body is logged. The full private request still needs measurement at its authorized operator boundary; synthetic fixture lengths are not its size.

Tests cover actual installed viem/isows WS 1009 to loopback HTTP with a 1.2 MB synthetic request, exact replay in both validation modes, full-capacity qualification, HTTP raw strict-nonce errors, 413/timeout/cap/wrong-chain/changed-snapshot/missing-envelope refusal, concurrent draining, explicit close, immutable input, and no write/sign admission. Studio runs the production SDK factory and both transport layers through its initial-storage service, with discovery/strict/full-metadata failures and UI/agent/managed-plan parity. Database, artwork and wire responses in those service tests are synthetic. `scripts/probe-approved-sepolia-http.mjs` separately reports the live public-only 200,000,000-gas HTTPS capability; neither a public probe nor offline tests proves the private plan or publication.
