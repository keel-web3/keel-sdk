# Stateful publication simulation

This implementation is experimental and is not selected by the production
transport factory. It does not issue a wallet approval on its own.

Storage publication already consists of separate transactions. A provider's
aggregate `eth_simulateV1` request budget is different from the chain's limit
for each transaction. Sending smaller independent RPC requests loses the
simulated writes from earlier requests. The local session adapter retains
those writes in one private native EVM state while executing the original
transactions in separate simulated blocks.

The paid release's final wallet batch remains one outer transaction. Its
underlying calls must not be split to evade atomic validation. Existing paid
storage receipts, release identities and exact metadata remain authoritative.

## Shared validation boundary

`packages/sdk/src/local-simulation-session.ts` accepts the complete immutable
request generated by `simulateKeelPublicationBeforeFunding`. It starts a native
session, sends each original block in order, and returns only the complete
ordered result after finalization and a canonical block recheck. The existing
SDK still checks transaction envelopes, fork headers, execution status,
pre-refund gas, strict transaction validity, required return assertions, and
the complete token URI.

Discovery and strict validation start separate sessions from the same original
state root. A discovery result cannot seed strict validation. No gas clipping,
state override, balance override, header override or transaction submission is
supported by the adapter.

Studio's initial storage checks, updated reviews and paid release checks share
its publication transport factory. HTTP and MCP use those same services.
Request-scoped cleanup and cancellation must discard late results before a
ready proof is saved; creator selection, revision checks and funding-history
reconciliation remain separate gates.

## Authenticated state

The native engine source is maintained under
`scripts/native/canonical-state-engine`. It uses the pinned upstream Geth EVM
and simulation implementation. A complete RLP header commits to the canonical
number, hash and state root. Account and storage proofs are verified against
that root, and runtime bytes must match their proved code hashes. Header
ancestors must form a hash-linked chain when execution accesses them.

The engine imports proved trie nodes into a sparse native StateDB. Missing
nodes, code or accessed ancestors are errors; they never become assumed zero
balances, storage, empty accounts or fabricated block hashes. Native system
calls and every later transaction use the same checks. A final successful
access-closure statement covers only the complete executed program, not every
account on the chain.

The engine preserves actual EVM transaction semantics. A contract revert
returns status zero and retains the outer transaction's normal nonce and gas
effects; the SDK rejects that result. A missing-witness or native execution
boundary error restores the pre-stage state copy and terminates the session.
Neither result can authorize publication.

## Retry and lifetime

Session identity binds the complete serialized program and canonical header.
Each stage binds its index and predecessor checkpoint. An exact acknowledged
stage retry returns the cached result without executing twice. Changed
digests, stale checkpoints, missing stages and incomplete finalization fail.

Cancellation destroys the request's local process. Reload or a new review
starts from the original authenticated snapshot and rechecks current source
and chain state. It cannot reuse another request's tentative state or revive a
cancelled review. Process cleanup is bounded; cleanup failure cannot turn an
otherwise successful result into an approval.

Ordinary chain reads and project-bearing estimates use separate explicit
capabilities. This adapter does not choose a recipient or fall back to a new
provider. The private native process runs with verified network isolation.

## Qualification limits

Mechanism fixtures demonstrate native continuity, rollback, retries and full
SDK result validation. They are not acceptance evidence for a creator's
project. A seed account proof is also not a complete project witness.

Actual project qualification requires a fresh source-assembled program and
complete sequential access closure at one canonical pin. Source revisions,
job IDs, factory nonces, predicted addresses, runtime identities, fees and
complete metadata must remain bound to that capture. An expired original is
preserved as an expected failure; renewal is a separately reviewed candidate.
Historical state or an old proof must not be silently moved to a new block.

Do not activate this path from successful mechanism tests alone. Record the
exact source, engine, witness, full-program and complete-return evidence, then
run the existing publication validator and freshness checks on the actual
saved plan before making a wallet proposal.
