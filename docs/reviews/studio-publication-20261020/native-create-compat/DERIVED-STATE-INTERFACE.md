The existing production proof transport starts a fresh ephemeral process for each
eth_simulateV1 request. Its getCode path reads the authenticated canonical base;
it cannot expose hypothetical future contracts to a normal compiler. The
following isolated CAPACITY_ONLY contract is proposed for the reader specialist's
normal f11/b524 GIF compiler bundle. It is not a new storage protocol, a public
API or an assertion that prerequisites have been deployed.

The source tuple remains Site f11, SDK b524, Contracts 6e (current49d production
bytecode) and Modules cd97151. Prefix input binds the current49d three CREATEs:
formatter, maintained factory and native media module; exact sender/nonces
296/297/298, initcode hashes, gas/fee/value fields, expected six created addresses,
compiled runtime/link identities and actual canonical header. No 4015/two-CREATE
or old 30-million module-gas packet is accepted. The consumed public attempt is
preserved and is not an admission for this new local capacity phase.

One reviewed initialization executes the unchanged three-call same-block prefix
through real Geth whole-block pre/post processing on an authenticated base state.
It records both sourceCanonicalAnchor N and the actual derived result header N+1
and holds its resulting StateDB S1. No balance/nonce/code/state/block overrides
exist. Before/after canonical and pending owner checks must preserve actual N;
the derived owner must be exactly N+3, with real charged balances. Expected code
comes from actual execution, then is compared to compiled current49d commitments.
It is never supplied as a fixture replacement for missing execution.

The Node boundary remains `createCapacityDriver({packet, signal})`, with the
reader's existing compiler hooks:

- `wrapClient(actualPublicClient)` routes bounded getters/code reads for only the
  six prefix-created identities to S1 and the actual derived header. A getter
  executes against StateDB.Copy with bounded gas; its changes are discarded.
  Creator nonce/balance reads may expose the actual derived N+3 state only inside
  this visibly simulated compiler context. The real pending N is rechecked.
- `projectFactoryRecords(actualRows, chainId)` creates only a hypothetical current
  factory projection. It does not borrow a legacy database ID, receipt or start
  block, and records `LOCAL_SIMULATED_ONLY` provenance.
- `projectInlineCatalog(parsedActualCatalog, chainId)` supplies only the actual
  derived module/formatter identities after the existing catalog parser. No
  deployment transaction hash or publicly verified registration is invented.
- `assertNativePrerequisiteIdentity(...)` compares actual S1 runtime bytes,
  formatter links, module fields and the current SDK factory/deployer/carrier/
  library/chain/domain qualification. It cannot substitute expected source bytes
  for a VM response. `close()` cancels/reaps work and disposes the held state.

No fake getTransactionReceipt is added. Only the two explicit missing-receipt
seams identified by the reader specialist may be instrumented in the isolated
bundle; actual SDK factory fingerprint and Site module/formatter/domain/pin
checks remain executed. The source manifest must bind both uninstrumented f11
inputs and the exact reversible instrumentation, with no production source edit.
Original GIF descriptor/source bytes and WebP preview commitments, owner/project/
revision and the original stage-signer policy remain exact.

Never forward derived-head N+1 state requests to public RPC: its public block N+1
is a different state. Created-address reads/getters are local S1 operations.
Historical receipt/header reads remain actual canonical reads. Other state reads
must execute locally on S1 or use explicitly proven unchanged canonical-N bytes,
with prefix write-footprint evidence; otherwise reject them. Do not silently
translate or relabel a counterfactual hash as public-canonical proof. Upstream
requests remain only the approved authenticated state/header/code methods, with
existing denial, cancellation, pacing and bounded-resource policies.

A whole-program capacity continuation starts from S1 AND its actual N+1 header.
Each subsequent publication block uses the normal Geth pipeline at N+2 onward,
including fees and system processing. Do not resume S1 under the old N header,
strip a prefix block and renumber output, or claim an unmodified canonical SDK
proof from a changed block context. The compiler capture must record both anchors
and the simulated namespace explicitly. Every original execution field remains
bound to the reviewed captured program; no stale deadline or pin is hand-edited.

Initialization/compiler capture and private complete-program execution require
separate exact source/input/containment reviews. Do not hold an engine across
review or reuse a consumed execution admission. A fresh independently admitted
run reconstructs the same reviewed prefix at its still-valid authenticated pin.
Ordinary and strict validation modes must retain their actual flags and limits;
no failed run is silently retried with different semantics.

This produces preapproval CAPACITY_ONLY evidence, not live Gate4/6, production
SDK canonical proof, deployment receipts or wallet acceptance. The preferred
final path is owner approval of a concretely qualified three-CREATE request,
actual receipt/runtime/selected-chain registration verification, then fresh
uninstrumented normal GIF preparation and complete deployed Studio proof. Wallet
signing/spend and any mandatory security approval remain the user's action.
