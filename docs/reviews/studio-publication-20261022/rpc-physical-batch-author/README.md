## Scoped change

Site owns`server/chain/public-client.ts`,`configured-read-batch.ts`; SDK owns`public-simulation-pool.ts`,`provider-request-scheduler.ts`. A publication batch wrapper collects only same-turn reads belonging to its exact owner/phase/recipient. Max 16 members / 64 KiB full UTF-8 HTTP envelope; a large existing individual read keeps the existing singleton request allowance. SDK bounds pending logical members at 64, splits conservatively before dispatch, and the HTTP validator checks the exact final envelope. Existing 250 ms admission and one physical slot apply per physical body. There is no response cache, extra retry, provider selection, enlarged phase deadline or changed transaction field.

All member outcomes settle before success delivery. Original non-denial errors and successful results remain associated with the exact request. Unsupported methods restrict their actual methods; 429 keeps existing cooldown/retry ownership. Numeric access denial restricts the whole provider. A synchronous fetch-layer denial hook records the restriction before viem can replace an error with cancellation; the helper additionally retains its own terminal restriction. Cancellation of noncooperative work keeps its physical slot occupied until settlement.

Viem 2.55.19 sorts returned IDs but does not validate exact membership before associating results. The new bounded validator checks actual request IDs and response version, complete unique membership and result/error exclusivity before the existing parser. Out-of-order valid replies work; missing, duplicate and unexpected IDs fail closed. HTTP 401/403 is terminal before body parsing; completed JSON-RPC 401/403 is terminal even in an otherwise invalid envelope. Bounded response clone reads retain the unchanged 10 MiB viem response bound, 20 s ordinary read timeout, owner signal, and cancel both tee branches on failure. No raw response/provider text is logged.
