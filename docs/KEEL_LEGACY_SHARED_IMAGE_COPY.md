# Legacy shared collector image

`buildKeelLegacyPreparedDenseDocument({ sharedCollectorImageResourceId, ... })` explicitly selects the optional `keel.legacy-prepared-dense-shared-image@1` shell. Every original runtime resource remains in order, including the image's IDs, aliases, media type, role, byte length and SHA-256. The image becomes a verified direct image slot; all other resources retain the existing 512 KiB decoded leaf, per-leaf codec selection and Dense COPY policy. Existing exact module fragments remain unchanged.

The returned `sharedCollectorImage.documentPartIndex` names a return-only Base64 slot. Do **not** upload that part. Store the native image once using its ordinary exact uncompressed object plan. Pass that same object ID to the existing KEEL721 image module and to `encodeKeelLegacySharedImageCopyProgram`. Bind other COPY steps using the exact already staged object IDs and stored digests. The encoder requires `null` at the image slot and rejects malformed graph commitments or noncanonical program data.

The program's `integrity` commits its small stored ABI descriptor; `renderedIntegrity` separately commits the expanded prepared HTML graph. Expanded preview bytes can remain in the local content store but are not an additional paid payload. The new `KeelLegacySharedImageTokenURIBuilder` checks every program/COPY/native-image commitment, generates the direct image return slot and verifies the complete rendered graph. It exposes the existing normal KEEL721 dynamic raw-percent harness interface. Use the existing image module and `setPreEncodedOnchainHarness` route. The literal-image immutable prepared-prefix route is deliberately rejected because it would store another image payload.

This is an explicit native-image composer capability, not an implicit `binaryPayloadCarriage` selection. Explicit Raw/native-as-is return constraints, explicit compressed image streams and creator-owned shells retain their existing choices. Supported dual-consumer raster media are PNG, JPEG, GIF, WebP and AVIF within the complete return/read limits. SVG and compressed collector-image bindings require their own compatible explicit reader and are not silently substituted.

The new program MIME is `application/vnd.keel.legacy-shared-image-copy-program`; it must remain an uncompressed explicitly selected entrypoint. Its exact builder runtime, deployed receipt, Hold binding, program profile, context builder, image module and distinct shell revision must be authenticated independently. Never relabel it as an old raw-percent fragment. The saved program, native image and local expanded graph have distinct commitments.

A modern Hold may require an exact prepaid weld intent, allowance and final root seal, plus registration of the program object/renderer pair. The program's ABI references are not Hold composite references. Sealing its descriptor does not pay for or seal its dependencies; every new source carrier still needs a valid paid or exempt upload allowance. Raw dependency reads do not inherently require another harness fee. `requireHarness` requires registration only when the configured viewer fee is nonzero, including for an exempt payer whose quote is zero. The recorded historical Hold without these APIs needs a separately authenticated compatible reader. Missing APIs never imply authorization.

The local compiled EVM/Chromium proof and its first failed attempts are retained in `recovery-evidence/legacy-shared-image-20261014`. The successful local proof uses actual normal collection/image-module contracts and a synthetic Hold storage/registration adapter. It is not proof of production Hold policy, a live public drop, selected-chain deployment, registration, publication or mint.
