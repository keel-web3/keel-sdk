# Smart asset presentation matrix

The shared browser-safe protocol planner is re-exported by `@keel/sdk/presentation`. Studio, SDK staging and MCP use the same enums, source inspection, thresholds and revisioned defaults. This document describes review policy, not deployed reader capabilities or a payment approval. Current product authority is the [Studio owner requirements](https://github.com/keel-web3/keel-site/blob/master/docs/STUDIO_PUBLICATION_REQUIREMENTS.md); actual completion is recorded in the [sprint ledger](https://github.com/keel-web3/keel-site/blob/master/docs/gauntlet/publication-sprints.json).

`planKeelSmartAssetPresentation` returns nine maintained slot combinations, their actual-adapter qualification requirements, hard blockers, compatibility warnings, provisional measurements, a recommendation and the preserved explicit selection. The friendly presets are `automatic`, `external-preview`, and `inline-image-hybrid-verifier`. Saved explicit candidate IDs and nonstandard compatibility understanding are independent of transaction authority. External preview URLs stay project-specific. Exact project/revision/default revision, source and preview SHA256/size/MIME/native object references, slot choices, selected chain/code identity and measurements enter the immutable plan identity.

The decimal 500,000-byte exception applies only to an inspected **static raster** that otherwise requires duplicate image and animation slots. Above it, automatic mode recommends the compatible image-only route; advanced creators can still select the verifier and save that preference. It never applies to GIFs, other animation, scripts, video, audio or 3D. Unknown motion/execution is not static. The default for these works is the registered verifier and their intended player/viewer. The separate 2,000,000-byte source threshold can recommend split-read verification but is not an import/storage ban or a complete-output measurement. A different source, lower-quality image, duplicate paid payload or invented reader is never a remedy.

The 1,750,000-byte encoded-image and 2,000,000-byte complete-metadata values are compatibility targets. Above them the matrix warns, preserves an explicit acknowledged choice and still requires the actual reader/provider/gas limits and complete-program simulation. Image-plus-hybrid over target offers image-only or verifier-only alternatives, with an explicit missing-grid-image warning for the latter. Only an actual measured embedded verifier alone above target suggests IPFS/hosted delivery; nothing is dropped or externalized automatically. Every fallback requires its real package commitment, public delivery and actual consumer qualification.

`measureKeelSmartAssetPresentation(plan, renderTokenURI)` requires the complete chosen metadata data URI. It measures UTF-8 and all actual outer encoding, verifies inline image bytes against the exact selected SHA256, checks slot semantics, and records the complete embedded animation/program identity and size. It does not assume a fixed-size root loader or omit reconstruction instructions. `measureKeelSmartPresentationMatrix` measures only adapters that exist; unavailable candidates remain unavailable. It snapshots input before awaits and reports actual alternative measurements. All results remain `publicationReady:false`; normal simulation and wallet commitment gates are mandatory. The coordinated explicit nonstandard-read policy must reach existing SDK guards before any greater-than-default return can pass them.

Current-route qualification remains explicit: image-only metadata requires its real compatible composer, and any shell/reader/module needs selected-chain code, registration and exact public read-back evidence. A plan must not fabricate image-only metadata through a manifest-as-animation fallback. Retired formats are not compatibility targets or fallback publication routes. Preserve original projects, blobs, permissions, receipts and rollback when a new preparation is required.

Older implementer test totals in previous revisions are historical observations,
not fresh approval of this source or a deployed release. The sprint ledger owns
current exact-commit independent normal-service, provider, browser, simulation and
unsigned-wallet verdicts. This policy page grants no transaction or payment approval.
